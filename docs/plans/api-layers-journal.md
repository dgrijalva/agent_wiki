# Journal: API layers

Plan: `docs/plans/api-layers.md`. Design: `docs/design/agent_wiki.md` → Host API, Live updates.

## 2026-10-21

- Design session with Dave: drawing layers, custom pages, live updates by URL, Folder/Document API with watches, host entity types, reindexing. Captured in `a7515f6`.
- Worktree `dg/api-layers` created with the `worktree` CLI; the design capture moved over from the main checkout as the first commit.
- Parse cost measured against Dave's vault (608 files): ~0.5 ms per typical document, ~2 ms for the largest; 100 typical documents in 49 ms single-threaded, 14 ms on 12 threads.
- Plan written. Dave: "build it".
- Step 1 built: `Element::draw(&self, cx)`, `cx.draw_children()`, `BodyCtx::draw`. Every in-tree `Element` impl updated; `Sized` bound dropped from the trait.
- Step 2 built: `src/data.rs` (`Folder`, `Document`, `Entry`, `Walk`, `DocumentBody`, `SearchOpts`, `LinkPage`), `Wiki::{root, lookup, search, tagged, link_target, draw}`; the internal parse result is now the public read-only `DocumentTree`, with `NodeRef`/`KindRef`. The document page is drawn from `Document::load` + `body()`. Added beyond the plan: `Wiki::tagged` and `Wiki::link_target`, so the tag and disambiguation bodies can be built from public data; `Wiki::draw` for drawing an element outside a page.
- Steps 3–4 built: `src/signals.rs` replaces the broadcast channel. Document and folder watches; open pages keyed by URL path, the stream at `{base}/_wiki/events?url=…&tab=…`; `Wiki::signal`; `Wiki::custom_page(…).live().draw(…)`, `PageKind::Custom`. Only document pages get a tab. A page's channel is held weakly by its stream, so dropping the wiki still ends open streams.
- Step 5 built: `src/components.rs`. Elements `SearchBox`, `Breadcrumbs`, `TagLinks`, `CopyPath`, `FrontmatterTable`, `RecentlyEdited`, `Contents`, `TagCloud`, and the page bodies `FolderIndexBody`, `SearchBody`, `TagBody`, `DisambiguationBody`, `NotFoundBody`, each loaded from the data layer then drawn. The built-in pages and the `BodyCtx` chrome methods are drawn from them. `BodyCtx::wiki()`; `PageKind::{FolderIndex, Tag, Disambiguation}` now carry their path, tag or target. Markup unchanged, except a listing entry now shows the summary before the page is indexed. `Index::listing_details` removed (`details` covers it).
- One unreproduced failure during step 5: a libsql `Transaction` drop panicked on rollback (`SqliteFailure(21, "bad parameter or other API misuse")`, `libsql-0.9.30/src/local/transaction.rs:26`) in `tests/web.rs`, and a following request in that test returned 500. 21 more full runs, on this branch and on main, didn't reproduce it.
- Step 6 built: `PRAGMA user_version` now holds `schema_version()`, an FNV-1a hash of `SCHEMA` and `INDEX_VERSION`; `Index::reset`; `Wiki::reindex()` (reset, then a full scan); `--reindex` on the binary runs it in the background at startup. `Entry::Document` is boxed (clippy: variant size).
- Step 7 built: `src/entity.rs` (`Entity`, `Field`, `FieldKind`, `FieldValue`, `EntityField`, `Records`), the `agent_wiki_derive` crate (`derive/`, a workspace member, re-exported as `agent_wiki::Entity`), `WikiBuilder::entity::<T>()`, `Host::extract(&self, path, doc, out)`. The index: an `entity_version` table in `SCHEMA`; per type `entity_{name}` (records reference `page(id)` `ON DELETE CASCADE`, with `PRAGMA foreign_keys = ON`), a b-tree index per `index` field, an external-content FTS5 table and triggers for `fulltext` fields. On open, a type whose version differs is dropped and recreated and marked stale; the next scan extracts stale types from files it otherwise skips. Unregistered types' tables are dropped. `rebuild` drops entity tables before `page`. Validation at `build`: names, reserved field names (`id`, `page`, `ordinal`), full-text only on text, no duplicates. `extern crate self as agent_wiki` so the derive works in the crate's own tests.
- Records aren't readable through the public API (querying is deferred), so the integration test only checks registration and extraction run; storage is checked by the unit tests in `index.rs` through SQL.
- Built-in `wikilink` and `tag` tables not moved onto the entity mechanism (plan: provisional).
- Checked in headless Brave: a document page live-updates through the new `/_wiki/events?url=…` stream when its file changes.
- Full suite (209 tests), clippy (workspace, all targets) and the marker lint are clean. Nothing committed.
